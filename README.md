# Coding Prep

A structured practice log for algorithmic problem solving, organized by pattern rather than by source or difficulty.

## Why this exists

Most problems that look unfamiliar at first glance are just a known pattern wearing a different disguise — a scenario about fraud detection, session logs, or delivery routes is often just a sliding window or a graph traversal underneath. The goal here isn't to memorize solutions, but to build the habit of recognizing the underlying pattern quickly, reasoning through trade-offs out loud, and writing clean, correct code without relying on autocomplete or a run button.

Each folder groups problems by the technique they exercise, so patterns can be revisited and reinforced over time rather than practiced once and forgotten.

## Structure

Problems are organized into folders by pattern:

- `two-pointers/` ✅
- `sliding-window/` ✅
- `binary-search/`
- `linked-lists/`
- `trees-bfs-dfs/`
- `graphs-bfs-dfs/` (includes `matrix-grid/` ✅, `topological-sort/` ✅, `union-find/`) ✅
- `backtracking/`
- `dynamic-programming/`
- `heaps-top-k/`
- `intervals/` (includes `prefix-sums/`) ✅
- `monotonic-stack/`
- `tries/`
- `mock-interviews/`

Each problem file typically includes a brief restatement of the problem, any clarifying assumptions made, the approach taken, and its time/space complexity.

## Approach

- Read the problem as if it were a vague, real-world scenario — ask clarifying questions before jumping to code.
- Write in plain text first (pseudocode or comments), then implement.
- State the complexity out loud after each solution, and consider whether a better approach exists.
- Revisit old problems periodically rather than treating each one as done forever.
